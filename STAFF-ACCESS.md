# Order Staff access

Administrators manage individual staff accounts under **Admin → Staff Accounts**. Creating an account, enabling/disabling access, or resetting a password requires the administrator's current password. Existing administrator authentication, MFA, one-hour sessions, CSRF protection and shared rate limits remain in force. Staff cannot create other staff or change their role or email.

Share `/staff/login` and the temporary password through a private channel. Passwords must meet the existing 15-character / 72 UTF-8 byte policy. The temporary password must be changed before any orders or notifications are accessible. The administrator can reset a forgotten password; existing customer/seller accounts cannot be converted into staff accounts. No initial staff account or default password is seeded.

Staff can view recent orders, open delivery details, receive unread notifications with optional sound, and change their own password. Orders, finance, payouts, refunds, product/seller management, customer exports and platform configuration cannot be changed through staff access. Order list responses omit delivery details and secret tracking credentials; package responses omit commission and settlement fields. Delivery details are loaded on demand. Staff can see orders across all sellers, so assign accounts only to employees authorized to handle delivery information.

Each staff session lasts at most eight hours and expires after 30 minutes without reported human interaction. Signed tokens and server-side session records both enforce expiry. A bounded activity request is sent on real pointer/keyboard interactions in the order monitor, at most once per minute; automatic notification polling and order reads do not extend idle sessions. An expired session cannot be revived by the activity endpoint. Disabled accounts, administrator password resets, staff password changes and sign-out revoke prior access. Session cookies preserve Secure/HttpOnly/SameSite protections. Session records expire through TTL indexes and are excluded from backups.

Order notifications are saved in the checkout transaction for each active staff account, with a separate read state per recipient. New staff members can view existing orders but receive alerts only for orders placed after their account is created. Disabled staff receive no new alerts. Dashboard alerts require a valid session and an open browser; this feature does not add email, SMS or push delivery while logged out.

Staff and order lists return at most 25 records, using indexed cursor pagination. Notifications retain their indexed 20-record limit, visible-only polling and backoff. Dashboard code and admin staff controls load as separate lazy chunks. No new dependencies or customer-facing background polling are added. Shared database session checks apply only to staff.

Administrator account changes are durably audited in the existing audit stream. Staff sign-ins, denials, password changes and delivery-detail views use the redacted security event stream. Tests cover lifecycle/access control, temporary passwords, cookie/CSRF protections, expiry and revocation, notification isolation, bounded indexed reads, backups, React error/idle handling, and desktop/mobile provisioning and order monitoring.

Before production release, run `npm run verify` and pass the repository's required **Marketplace verification** CI check on the exact release revision. Production publication remains gated by that check. Hosted capacity, real employee provisioning and out-of-session alert delivery are separate operational concerns.
